# Final Price Golden Set v1

**500 synthetic cases · 25 rule families · 156 fictional policy documents**

These labels were generated by explicit scenario logic and an independent exact-rational, integer-cent oracle. They are **not human-annotated production ground truth**. Human policy-owner review is pending. Do not copy the historical percentages in the resume brief into a report for this dataset.

## Files

- `cases.jsonl`: one case per line, including a natural-language question, related source document IDs, reference assertions, reviewed policy inputs, explicit order facts and expected result.
- `corpus.jsonl`: the canonical fictional documents for retrieval evaluation. The graph sees these documents, never the expected answers.
- `manifest.json`: counts, provenance, per-family coverage and SHA-256 fingerprints.
- Generator: [`evaluation/golden/generate.py`](../../../evaluation/golden/generate.py).

Each case has a `family`, `pair_id`, `split`, `relevant_documents`, `reference_claims`, `policies`, `order` and `expected`. A calculation expectation contains the final currency/price, a reference expression, required source names and expected exclusions. Clarification cases contain a reason and no numeric target.

## Coverage

Each family has 20 cases. Numerical boundaries include one cent below, exactly on and immediately above relevant thresholds across paired scenarios.

| Area | Families |
|---|---|
| Threshold semantics | Threshold boundary; repeated full-spend reduction; original versus remaining threshold basis; once per order |
| Parentheses and scope | Parenthetical exclusion; nested exception; AND/OR grouping; illustrative parentheses; negation |
| Combination and amounts | Discount cap; order of operations; exclusive best offer; category restrictions; coupon claim/validity; final half-up rounding; zero floor |
| Time | Inclusive validity endpoints; rule-specific subperiods; unknown validity |
| Abstention and robustness | Missing membership; missing rounding; conflicting equal-authority rules; malformed OCR parentheses; malicious instructions embedded as policy data |

There are **390 calculation cases and 110 clarification cases**. All 500 questions are unique. There are 100 development cases and 400 evaluation cases, separated by entire rule family to reduce template leakage. The evaluation split is still synthetic and has been inspected during development; it is **not an independently held-out human benchmark**.

The 20 malformed-upload cases deliberately differ from their valid canonical source. They test the upload integrity gate, not retrieval of a malformed document. Therefore real retrieval runs explicitly evaluate **480 cases**, while upload-price outcome runs evaluate all **500**.

Some multi-case threshold families have separate named campaigns and source IDs. This prevents contradictory versions of the same promotion from creating ambiguous retrieval labels. Retrieval uses only the approved-status filter, without event/category filters that would trivially reveal the gold documents.

## Reproduce

From the repository root:

```bash
# No LLM calls: reproduce and check all fixtures/labels.
.venv/bin/python -m evaluation.golden.generate
.venv/bin/python -m evaluation.golden.benchmark --mode validate

# Actual configured pricing model; uses API credits. Checkpoints every case.
.venv/bin/python -m evaluation.golden.benchmark --mode agent \
  --concurrency 6 --output reports/golden-500-agent.json
# Add --resume to continue an interrupted identical dataset/model/implementation.
# After restoring API credits, add --resume --retry-errors to retry service errors only.
# Earlier reports and all checkpoint attempts are preserved.

# Real ES + BGE + Cross-Encoder. Launches/removes only a disposable test container/index.
.venv/bin/python scripts/evaluate_golden_retrieval.py \
  --output reports/golden-480-retrieval.json
# First run downloads the models. Set HF_HOME to a writable cache if needed.

# Assertion-level audit of one saved response per family (25 cases, not all 500).
.venv/bin/python -m evaluation.golden.judge \
  --responses reports/golden-500-agent.json --limit 25 \
  --include-tool-trace --output reports/golden-25-assertions.json
```

`--mode validate` checks uniqueness, schema, generator reproducibility, source references, family-separated splits, bracket integrity and agreement between the independent cents oracle and Decimal for all 390 numeric labels. It does **not** run the AI agent and cannot be reported as model accuracy.

If the provider reports exhausted credit, the runner stops new model calls, still evaluates local integrity/date guards, and marks remaining model-dependent cases as not run. It never purchases credits.

The model runner reports outcome correctness, exact price, policy exclusions, citation recall, invalid-plan responses, false-price cases and provider failures. Provider errors remain in the overall denominator. Clarification scoring checks the requested action and absence of a computed amount; it does not by itself verify that every clarification reason is complete.

The retrieval runner records all four configurations, stage traces, actual selected context, Recall@5, Precision@5, MRR@5 and latency. It does not generate answers. The optional `--include-tool-trace` flag supplies trusted Decimal execution evidence alongside policies/order facts, so claims about executed arithmetic are not judged solely against policy text. Both policy-only and tool-aware audits can be retained.

The separate assertion audit is a sample of uploaded-policy answers, not an end-to-end retrieval-plus-generation faithfulness measurement. The configured judge is the same model by default, so its judgments are not independent human labels.
